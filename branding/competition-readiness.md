# Ansik — 공모전 완성도 검증 계획

## 제품의 중심 문장

한국 음식이 낯설고 식사 제약이 있는 여행자가 메뉴를 이해하고,
식당에 확인할 사항을 알아보며 여행을 계획하는 서비스.

건강 안전을 인증하거나 진단하는 서비스가 아니다. 메뉴의 일반적인
재료 설명과 해당 식당이 확인한 실제 조리법을 혼동하지 않는다.

## 이번 변경

- 일반 조리법 기반 AI 참고 분석임을 메뉴 분석 카드에 명시.
- '괜찮아 보임'을 '충돌 미확인'으로 바꾸고 안전 인증처럼 보이는 녹색 배지를 제거.
- 코스 생성의 고정 시각 배정 대신 이동거리/체류시간 기반 추정값 사용.
- 첫 장소와 식당의 순서상 위치를 고정하고 나머지 순서를 거리 기준 비교.
- 1~2개 장소에서도 시간 계산이 실패하지 않도록 수정.
- 긴 이동, 늦은 종료, 좌표 부족에 대한 경고.
- 사용자 입력 일정은 기존과 같이 순서/시각 보존. 자동 재계산 대상으로 삼지 않음.

## 한계 — 발표에서 실제보다 과장하지 않을 사항

- 이동시간은 경로 API 실측값이 아니다. 실제 이동수단/환승/교통/도보 접근성 미확인.
- 추정 정책: 직선거리 × 1.4, 근거리 4km/h, 그 외 18km/h + 접근/대기 여유.
  이는 계획용 가정이며 통계로 검증된 평균값이 아니다.
- 체류시간은 식당 60분, 쇼핑 75분, 그 외 90분의 제안값이다.
- 영업시간과 휴무일은 이 시간 계산에 반영되지 않는다.
- 식당 간 순서상 위치 보존은 점심/저녁 시각 보장을 뜻하지 않는다.
- AI의 재료/건강 설명은 식당 확인 정보가 아니다.
- 자동 테스트 통과는 실제 여행 및 실제 사용자 검증을 대체하지 않는다.
- 승인 대기 애니메이션은 앱에 적용되지 않았다.

## 제출 전 검증표 (실측 미실시 — 결과를 채워야 함)

| 대상 | 제안 표본 | 기록할 결과 |
|---|---:|---|
| 식당 장소·주소 매칭 | 서로 다른 지역 30곳 | 정답/오매칭/정보없음, 확인 URL/날짜 |
| 메뉴 이름·사진 | 100개 | 실제 메뉴/일반 음식 이미지 구분, 오매칭 비율 |
| AI 설명 | 위 메뉴 동일 표본 | 근거 없는 식당별 주장, 정보 부족 표시 여부 |
| 일정 실행 가능성 | 3개 지역 × 3코스 | 이동·영업시간 대조, 과밀 일정, 수정 필요 개수 |
| 사용자 입력 일정 | 정상/짧은 입력/오타/모순 각 5개 | 장소 보존, 누락, 확인 필요 안내 |
| 다국어 | 한국어/영어/일본어/간체 | 번역 누락, 긴 문구 잘림, 의미 왜곡 |
| 네트워크 장애 | 검색/생성/분석 | 재시도, 기존 결과 보존, 중복 요청 |
| 사용성 | 대상 사용자 5~10명 | 핵심 과제 성공 여부, 소요시간, 막힌 지점 |

표본 수는 이번 작업의 검증 제안이며 공식 심사 기준이 아니다.
실제 식재료 확인 없이는 건강 안전의 '정답률'을 측정하거나 주장하지 않는다.

## 발표 시연 흐름

1. 음식 선택에서 사용자가 겪은 구체적인 어려움.
2. 건강·식사 조건 및 언어 선택.
3. 공공 관광데이터의 실제 장소로 코스 생성.
4. 식당 메뉴 설명과 확인할 사항 비교.
5. 지도에서 동선 확인 및 일정 저장.
6. 검증 결과와 아직 해결되지 않은 한계를 함께 제시.

## 후속 필수 작업

- 날짜/이동수단 입력을 받아 경로 제공자의 이동시간과 영업시간 검증 연결.
  신규 유료 API는 요금 및 권한 확인 후 적용.
- 메뉴 사진은 일반 음식 예시와 실제 식당 사진을 명시적으로 구분.
- 개인정보/건강정보 처리 및 서비스 운영 설정 점검.
- 대상 사용자 테스트는 실제 참가자를 모집한 뒤 실시. 결과를 만들어 넣지 않는다.
