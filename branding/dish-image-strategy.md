# 음식 대표 사진 개선안

2026-09-14 조사. 이번 작업에서 사진 공급자를 교체하지는 않았다.

## 현재 문제

서버가 AI가 만든 imageSearchQuery를 NaverService.getMenuImages에 전달한다. 제목에 요리명이 포함되는지, 이미지 크기와 URL 등을 검사하지만 사진 자체가 그 요리인지는 검사하지 않는다. 영상 제외와 해상도 제한만으로는 오매칭을 해결할 수 없다.

## 권장 구조

1. 메뉴명을 표준 요리 ID로 연결한다. 번역 표시명과 사진용 ID를 분리한다. 소불고기/돼지불고기, 물냉면/비빔냉면은 별개로 관리하고 불명확한 세트 메뉴는 자동 연결하지 않는다.
2. 자주 나오는 메뉴부터 사람이 확인한 대표 사진을 등록한다. Wikimedia Commons 등에서 사용 조건을 확인한 이미지를 골라 원본 페이지, 저작자, 라이선스, 너비·높이와 함께 보관한다.
3. 등록되지 않은 메뉴는 음식 전용 API로 후보를 얻되 제목뿐 아니라 재료와 조리 형태도 비교한다. 필요하면 시각 모델로 추가 검사하고, 불확실한 후보는 검수 대기로 남긴다. 시각 모델 결과도 정답 보장은 아니다.
4. 앱에는 '요리 참고 사진 · 실제 매장 사진과 다를 수 있음'과 출처를 표시한다. 검증된 후보가 없으면 사진을 생략한다.
5. 사진 출처나 검수 결과가 바뀔 때 메뉴 가이드와 사진 캐시를 함께 갱신한다.

## 공급자 비교

| 후보 | 용도 | 확인할 점 |
| --- | --- | --- |
| Wikimedia Commons | 직접 검수할 대표 사진의 출처 | 파일마다 저작권·표기 조건이 다름. 검색 결과를 그대로 자동 채택하지 않음 |
| TheMealDB | 요리명·레시피·사진이 묶인 보조 후보 | 실제 한식 메뉴 커버리지는 별도 측정 필요. 공개 앱은 production key 조건 확인 |
| Spoonacular | 레시피 검색과 이미지 분석을 통한 보조 후보 | 한식 세부 메뉴의 일치율, 이용 조건과 요청 비용을 도입 전 측정 |
| Google Custom Search JSON API | 신규 도입 제외 | 신규 고객 가입 중단, 기존 고객도 2027-01-01 종료 안내 |

## 도입 전 검증

실제 앱 메뉴 50개를 고정한 평가 목록으로 구성한다. 일반 한식, 비슷한 요리 쌍, 국물/비국물, 세트/브랜드 메뉴, 음료를 포함한다. 현재 방식과 후보 방식의 정확한 요리 일치율, 사진 제공률, 로딩 실패율을 사람이 비교한다. 우선 잘못된 사진을 줄이고, 제공률은 검수 카탈로그를 늘리며 개선한다. 아직 실제 API 후보 이미지의 비교 평가는 수행하지 않았다.
